# SmartMix 智能混音网页开发规格

## 1. 项目定位

SmartMix 是一个面向普通音乐爱好者、活动策划者和轻量 DJ 场景的在线智能混音工具。用户上传一组歌曲后，系统自动分析 BPM、能量、调性和静音/段落特征，推荐更自然的播放顺序，并在相邻歌曲之间生成平滑过渡，最终支持在线试听和导出混音文件。

该项目参考 Mixxx AutoDJ 的设计思想：自动队列、可配置过渡模式、基于 intro/outro 的过渡时机计算，以及随机插入等播放队列能力。SmartMix 的第一阶段目标不是替代专业 DJ 软件，而是提供一个打开网页即可使用的自动混音工作台。

## 2. MVP 范围

第一版优先做成浏览器端可运行的原型，避免本地 Python、ffmpeg、Celery 等依赖阻塞验证。MVP 功能包括：

- 多音频文件上传，使用浏览器原生解码能力支持 MP3、WAV、AAC、OGG、FLAC 等常见格式。
- 文件列表管理：展示文件名、时长、BPM、调性、能量、状态；支持删除和上移/下移。
- 音频分析：估算 BPM、能量轮廓、粗略调性和首尾低能量区域。
- 自动排序：支持原始顺序、BPM 升序、BPM 降序、谐和优先、能量弧线和综合推荐。
- 过渡设置：用户可以设置交叉淡入淡出时长，选择固定过渡或根据首尾低能量区域自动收敛时长。
- 实时预览：使用 Web Audio API 按排序结果播放，并在过渡段执行淡入淡出。
- 导出 WAV：使用 OfflineAudioContext 离线渲染混音结果，生成可下载 WAV 文件。

## 3. 后续增强范围

后端增强版建议采用 FastAPI + Celery/RQ + Redis + ffmpeg：

- 后端持久化上传文件和分析结果，支持大文件、长任务和并发用户。
- 使用 librosa、essentia 或 madmom 做更稳定的 BPM、节拍网格、调性、段落和鼓点检测。
- 使用 pydub/ffmpeg 生成 MP3、WAV、FLAC 等格式。
- 增加波形编辑器，让用户手动调整每首歌的 cue、intro、outro 和过渡点。
- 支持节拍同步、变速不变调、EQ 过渡、滤波器扫频和多种 Mixxx 风格过渡模式。
- 增加项目保存、分享链接、云存储、任务队列监控和过期文件清理。

## 4. 用户流程

1. 用户打开 SmartMix 页面。
2. 拖拽或选择多首音频文件。
3. 页面自动解码并分析每首歌，分析完成后展示指标。
4. 用户选择排序策略和过渡时长。
5. 用户点击“应用排序”查看推荐顺序，也可以手动微调。
6. 用户点击“预览混音”在线试听。
7. 满意后点击“导出 WAV”，浏览器离线渲染并生成下载链接。

## 5. 分析算法设计

### 5.1 BPM 估算

MVP 采用能量包络近似算法：

- 将左右声道混合为单声道。
- 按固定窗口计算 RMS 能量。
- 对能量的一阶变化做峰值检测，得到 onset-like 序列。
- 在 70-180 BPM 区间做自相关，选择相关性最高的候选节奏。

该方法对电子乐、流行乐和鼓点清晰的曲目效果较好；对弱节奏、现场录音、古典音乐会偏粗略。后端增强版应切换为 librosa beat tracking 或更专业的节拍网格算法。

### 5.2 调性估算

MVP 使用抽样自相关估计若干片段的基础频率，映射到 12 个 pitch class，再用 Krumhansl-Schmuckler 大小调模板做匹配。该方案是轻量级估计，输出用于排序参考，不作为专业调性检测结果。

后续增强版建议使用 chroma_cqt/chroma_stft、HPCP 或 Essentia KeyExtractor。

### 5.3 能量与段落

能量指标取全曲 RMS 均值和峰值的组合。intro/outro 低能量区域通过首尾能量窗口低于阈值的连续时长估计，用于自动缩短或放宽过渡时间。

## 6. 排序策略

- 原始顺序：保留用户上传顺序。
- BPM 升序/降序：适合渐快或渐慢播放。
- 谐和优先：先选择一首歌作为起点，再用贪心算法最小化调性距离、BPM 差和能量差。
- 能量弧线：按能量从低到高再缓慢回落，适合活动暖场到高潮再收束。
- 综合推荐：综合 BPM、调性和能量距离，生成相邻差异较小的播放顺序。

综合评分：

```text
score = 0.55 * normalized_bpm_delta
      + 0.30 * key_distance
      + 0.15 * energy_delta
```

## 7. 过渡设计

MVP 使用 Web Audio GainNode 做交叉淡入淡出：

- 当前曲目在尾部 transitionDuration 秒内线性淡出。
- 下一曲在同一时间段线性淡入。
- 每首歌开始时间为上一首开始时间 + 上一首时长 - 实际过渡时长。

自动过渡时长：

```text
actual = clamp(min(userDuration, outroLowEnergy + introLowEnergy + 2), 2, userDuration)
```

当歌曲过短时，过渡时长限制为相邻两首歌较短者的 35%。

## 8. 前端信息架构

页面分为四个工作区：

- 顶部工作栏：产品名、文件上传、主要状态、核心操作按钮。
- 控制面板：排序策略、过渡时长、自动时长开关、播放/停止/导出。
- 曲目表：曲目指标、状态、手动排序和删除。
- 输出面板：当前混音统计、导出进度、下载链接。

视觉方向：专业音频工具感，深色背景、清晰数据表、醒目的播放状态和音频仪表感。避免营销落地页式结构，直接进入可操作工作台。

## 9. 技术架构

当前 MVP：

```text
index.html
styles.css
app.js
```

核心浏览器 API：

- File API：读取本地音频文件。
- AudioContext：解码与实时预览。
- OfflineAudioContext：离线混音渲染。
- Blob/Object URL：导出 WAV 下载。

后端增强版建议结构：

```text
backend/
  app.py
  analysis.py
  mixing.py
  jobs.py
  storage.py
frontend/
  src/
  public/
```

## 10. 验收标准

MVP 完成后应满足：

- 上传 3 首以上音频后，页面能逐首显示分析状态并给出 BPM、调性、能量和时长。
- 用户可以选择至少 5 种排序策略并应用到列表。
- 用户可以预览按当前顺序生成的交叉淡入淡出播放。
- 用户可以导出一个 WAV 混音文件。
- 分析失败的曲目不会导致整个页面崩溃，并能在列表里展示错误状态。
- 页面在桌面浏览器中布局稳定，按钮文字不溢出，主要工作流无需说明即可完成。

## 11. 当前开发计划

1. 建立静态网页项目。
2. 实现文件上传、音频解码和状态管理。
3. 实现 BPM、能量、粗略调性和 intro/outro 低能量估算。
4. 实现排序策略和手动顺序调整。
5. 实现 Web Audio 实时预览。
6. 实现 OfflineAudioContext 混音导出 WAV。
7. 本地打开页面做基础语法和交互验证。
